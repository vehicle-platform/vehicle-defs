## [0.26.0] — 2026-11-10

MINOR: declared inputs that no rule reads are removed (ISSUES E-30 (8); D-095 item 1: a declared input that the reference or rt-core never reads is a bug, corrected in defs without inventing a rule), and one dry-air gas constant replaces the consumers' two literals. No other description or value, DBC signal, ID, layout, scale, VSS path, DID, ride-record layout, poll, BLE, mailbox layout, `tester_policy`, D-020 golden copy or frame-gate change; `VEHICLE_CL250_DERIVED_INPUT_MAX` stays 6.

- `fuel_level_filtered`: `did.VEHICLE_SPEED`. `clutch_state`: `const.derived_throttle_closed_max_pct`. `clutch_slip_ratio`: `did.THROTTLE_POS`. `cold_engine_abuse`: `did.ENGINE_OIL_TEMP`. `launch_event`: `did.ENGINE_SPEED`, `did.THROTTLE_POS`, `derived.gear_estimate`, `const.gear_ratio_2..6`. `ride_warmup_time`: `did.RUN_TIME_SINCE_START`. `ride_final_drive_ratio`: `did.THROTTLE_POS`, `const.primary_reduction_ratio`.
- **`dry_air_gas_constant_j_per_kg_k` = 287.05 (calculated, ISO 2533 R* / M of dry air; ISSUES E-30 (10)):** a new constant and `const.*` input of `air_density`, `altitude_change`, `power_correction_factor`, `volumetric_efficiency` and `intake_flow_residual`; the first two descriptions now state the formula, the VE rule names the constant instead of a literal. The consumers hand-wrote 287.058 for the density and the altitude and 287.05 for VE: one value now, so `air_density` and `altitude_change` move by -0.003 % (`power_correction_factor` is a ratio of two densities and does not move).
- **Compile-time timing macros (gen/c, additive; ISSUES E-30 (10) history caps):** `VEHICLE_CL250_POLL_MS_<DID>` in `vehicle_cl250.h` (all C targets with the vehicle table), and in `vehicle_cl250_derived.h` `VEHICLE_CL250_PERIOD_MS_<SIGNAL>`, `VEHICLE_CL250_WINDOW_MS_<SIGNAL>` (signals with a window) and `VEHICLE_CL250_MAX_DURATION_MS_<WINDOW>`: copies of the table data so rt-core sizes its histories at compile time instead of hand-deriving them (the tables stay the runtime source; a codegen test keeps them equal).
- **`vehicle_defs.uds.RECORD_FIELDS` (Python, additive; ISSUES E-13 (3)):** the field positions (`{byte, mask}` / `{byte, length}`) and named values of every record/bitfield DID per node (e.g. 0xFD00, 0xFD02 `RT_CORE_HEALTH`, 0xFD03 `LEAN_HEALTH`), so host testers such as vehicle-hil-bench decode them from defs; the ride-summary records keep `RIDE_RECORDS`.
- **`PLATFORM_E2E_RANGE_<SAFETY|HEARTBEAT>_FIRST_ID/_LAST_ID` (gen/c `platform_e2e.h`, additive; ISSUES E-14 (5)):** the E2E-mandatory standard-ID ranges of the platform bus (0x010-0x07F, 0x080-0x08F, codegen `ID_RANGES`) and the predicate `platform_e2e_id_mandatory(id, extended)` over all of them, so a sender can refuse an unprotected frame there without hand-writing the ranges or their list.
- **Outputs can move:** both the vehicle-server reference and rt-core start a class-A signal's grid at the latest first sample of its declared inputs and need every declared input present, so a signal no longer waits for an input it never reads. Consumers: **vehicle-server** drops its `KNOWN_UNUSED` audit entries and the "declared, not used" notes and regenerates the golden vectors; **vehicle-rt-core** recompiles (its derived input table `vehicle_cl250_derived.c` changes) and takes the regenerated vectors.

## [0.25.0] — 2026-11-10

MINOR, additive: four derived-signal constants and the codes of three enum signals that the consumers hand-wrote until now (ISSUES E-30 (7), (10)); values unchanged, so no derived output changes. - **`j1349_reference_pressure_kpa` = 99.0, `j1349_reference_temperature_c` = 25.0 (provisional, D-070 item 6):** `const.*` inputs of `power_correction_factor`, whose description now states the rule (rho_ref / air_density, rho_ref = dry-air density at the two reference values).
- **Enum codes (`values`, new optional key of a `unit: enum` derived signal; codegen checks: integer codes within the range, unique snake_case names, no clash with a signal name):** `gear_estimate` {0: no_gear}, `clutch_state` {0: engaged, 1: disengaged, 2: slipping}, `neutral_coasting_state` {0: driven, 1: neutral, 2: coasting}. rt-core gets float defines `VEHICLE_CL250_DERIVED_VALUE_<SIGNAL>_<NAME>` in `vehicle_cl250_derived.h` (the table itself is unchanged), the Python reference `SIGNALS[name]["values"]`.
- New in `gen/c/rt_core/vehicle_cl250_constants.h` (four defines) and `gen/python/vehicle_defs/vehicle_constants.py`; `vehicle_derived.py` inputs/descriptions follow. Consumers: **vehicle-server** and **vehicle-rt-core** replace their literals at their next bump (golden vectors unchanged).

### Fixed
- codegen: cantools' C `<msg>_<signal>_encode()` truncated `(value - offset) / scale` toward zero, while the cantools Python reference (and every Python consumer) rounds. - tests (C-7): `encode()` now maps every raw value in the physical range back exactly (all of them up to 16 bits) and agrees with the Python reference for values up to 0.45 steps off, and returns the type limits past them (half a step, far, ±inf) and 0 for NaN, on every node, whether or not the node also has `decode()`.
