# Requirements-to-Tests Traceability Matrix (Proposed)

**Status: proposed** (idea note under `docs/ideas/`, not a recorded decision; no code changes). Prepared for thesis work package Ç8 (`ARCHITECTURE.md` §8–§9, D-113).

## Known conflicts and scope notes

- **No conflicts with recorded decisions.** Where `vehicle-defs/requirements/*.yaml` (D-113, provisional) already defines `REQ-<DOMAIN>-NNN` rows, this matrix keeps their IDs and cross-checks their listed test names against `main` across all 12 repositories.
- **D-135 compliance:** No vehicle-specific CAN IDs or proprietary CL250 DIDs are quoted; vehicle-bus rules reference `uds/vehicle_cl250.yaml` / `tester_policy`, and only generic platform-bus IDs (`0x010`–`0x08F`, `0x120`, `0xFD40`–`0xFD4E`) appear.
- **Stale links observed in `vehicle-defs/requirements/*.yaml` (proposed cleanup for Claude):** four YAML entries cite moved test filenames (`REQ-PLATFORM_BUS-001` cites `test_e2e.py` instead of `test_dbc_checks.py`; `REQ-TESTER-001` cites `test_uds.py` instead of `test_c_code.py`; `REQ-TESTER-002` and `REQ-TESTER-003` cite `test_uds.py` instead of `test_vehicle_checks.py`), and `REQ-PLATFORM_BUS-003` lists `tests: []` even though `test_dbc_checks.py` already asserts it on `main`.

## Coverage classification

- **tested** — at least one automated test on `main` explicitly asserts the requirement (file + test name cited in the table).
- **partial** — automated test(s) on `main` check part of the requirement, but another part remains unimplemented, unasserted, or hardware-gated (gap stated).
- **untested** — no automated test on `main` asserts the requirement (either the feature is not written yet or it lacks automated assertions).
- **needs hardware** — verification requires physical boards, harness, bench supply, HIL bench (T26/Ç4–Ç5), or on-vehicle trials (T0–T4).
